# Cat Duty V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the three cartoon Cat Duty characters with reference-accurate photorealistic cats and 12 real multi-frame actions while preserving the existing daily and two-hour rotations.

**Architecture:** Keep the existing `CatDuty` client component and its information bubble. Add versioned V2 static images and action sheets, move frame and action selection math into a small tested utility, and make the canvas renderer consume explicit action metadata with static and reduced-motion fallbacks.

**Tech Stack:** Next.js 16.2.9, React 19, JavaScript, Canvas 2D, CSS media queries, Node.js 22 test runner, OpenAI Image Generation.

**Spec:** `docs/superpowers/specs/2026-09-05-cat-duty-v2-design.md`

## Global Constraints

- 甜枣 is supplied Image 1, 三塔 is supplied Image 2, and 雪宝 is supplied Image 3.
- Preserve each cat's coat, face, eye color, collar color, and paw medallion across all assets.
- All V2 assets have transparent backgrounds with no scenery, text, borders, circles, or gutters.
- Each action sheet is exactly `4 x 4`, contains 16 square cells, and orders frames left-to-right then top-to-bottom.
- Keep the current daily duty rotation and two-hour action rotation.
- Keep the current bubble content, desktop position, and `< 768px` hidden behavior.
- Only the active action is loaded.
- Reduced-motion and action-load failure both display the static V2 master image.
- Existing V1 assets remain unchanged for rollback.
- Use the local NVM Node.js 22 runtime for tests, lint, and builds.

- [ ] **Step 3: Implement the pure functions**

Create `src/lib/cat-animation.js`:

```js
export function getCatActionForHour(actions, hour) {
  if (!Array.isArray(actions) || actions.length === 0) return null
  return actions[Math.floor(hour / 2) % actions.length]
}

export function getSpriteFrame(frameIndex, action, imageWidth, imageHeight) {
  const sw = imageWidth / action.columns
  const sh = imageHeight / action.rows
  const index = frameIndex % action.frameCount
  return {
    sx: (index % action.columns) * sw,
    sy: Math.floor(index / action.columns) * sh,
    sw,
    sh,
  }
}
```

- [ ] **Step 4: Replace pixel-scanning playback with metadata playback**

Change the signature to:

```js
function SpriteAnimation({ action, fallbackSrc, size = 200 })
```

Render a wrapper containing an `<img alt="" src={fallbackSrc}>` and the canvas. Keep the fallback visible until the first frame has been drawn. For each frame, call:

```js
const frame = getSpriteFrame(frameIndex, action, img.width, img.height)
ctx.clearRect(0, 0, size, size)
ctx.drawImage(img, frame.sx, frame.sy, frame.sw, frame.sh, 0, 0, size, size)
```

Use `1000 / action.fps` as the frame interval. Set an internal `ready` flag after drawing frame zero. On `img.onerror`, leave the fallback visible and do not schedule another frame.

Reset `ready` to `false` whenever `action` changes so the static fallback covers every action transition until the new sheet's first frame is ready.
